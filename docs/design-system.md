# 디자인 시스템 명세

> 스타일의 **규칙**만 적는다. 토큰 **값**은 [토큰 표](./tokens.md)(CSS 에서 자동 생성), 규칙을 그렇게 정한
> **이유와 이력**은 [결정 기록](./design-system-decisions.md), 공용 컴포넌트 **사용법**은 [components.md](./components.md).

## 읽는 법

규칙마다 상태를 붙인다.

| 표시 | 뜻 |
|---|---|
| **강제** | 이미 지켜지고 있고, lint·테스트가 막는다. 어기면 커밋·CI 가 실패한다 |
| **목표** | 앞으로 지킬 규칙인데, **아직 안 지키는 옛 코드가 남아 있다.** 괄호 안 숫자가 그 남은 곳의 수다 |
| **권장** | 막지 않는다. 리뷰에서 본다 |

**"목표"를 읽는 법** — 예를 들어 `3.7-1. 시간·곡선은 토큰으로. … — 목표(451)` 은
"`transition: 0.3s` 처럼 시간을 숫자로 직접 쓴 곳이 아직 451곳 있다"는 뜻이다(2026-10-01~02 에 센 수).

- 새로 쓰는 코드는 처음부터 이 규칙을 지킨다.
- 451곳은 [이행 계획](#11-이행-계획)의 해당 단계에서 고쳐 0으로 만든다.
- 그 전까지 이 숫자가 **늘면 안 된다**(새 코드가 규칙을 어겼다는 뜻). 이행 3단계에서 숫자가 늘면 실패하는 테스트를 둔다.
- 0이 되면 lint 규칙으로 바꾸고 "강제"로 올린다.

규칙 번호는 **절 번호-순번**이다 — `3.4-3` 은 §3.4(크기)의 세 번째 규칙.

## 1. 기반

| | 정한 것 |
|---|---|
| 스타일 방식 | **CSS Modules + 디자인 토큰** 하나. 유틸리티 클래스(Tailwind)·런타임 CSS-in-JS 는 쓰지 않는다 |
| 파일 | 컴포넌트 하나 ↔ `.module.css` 하나, 같은 폴더 |
| 반복 | 같은 스타일이 3곳 넘게 반복되면 CSS 유틸이 아니라 **React 컴포넌트**로 뽑는다 |
| 지원 브라우저 | `package.json` 의 browserslist — Chrome·Edge·Firefox·Safari 각 **최근 2개 버전**. 2026-10 기준 Chrome·Edge 150+, Firefox 153+, Safari 26.5+ |

**1-1. 새 CSS·HTML 기능은 [Baseline](https://web.dev/baseline) 이 된 시점으로 고른다.** browserslist 에는 iOS Safari 가
없고, 실제 방문자에는 업데이트를 미룬 iPhone 이 있다. 그래서 "지원 범위에서 된다"만으로 쓰지 않는다.

| 기준 | 기능 |
|---|---|
| **그냥 쓴다** — Baseline 이 된 지 1년 넘음 | cascade layer(`@layer`) · nesting · `:has()` · container query · `color-mix()` · `oklch()` · media query 범위 문법 · `<dialog>` · `light-dark()`(2024-05) · Popover API(2025-01 — iOS 의 바깥 클릭 닫힘이 18.3 에서야 고쳐져 늦게 인정됐다) |
| **없을 때도 괜찮으면 쓴다** — 1년 안 됨 | View Transitions(같은 문서, 2025-10) — 없으면 애니메이션 없이 바로 바뀌므로 쓴다 |
| **아직 안 쓴다** | CSS anchor positioning(2026-01, Firefox 147) — 없으면 팝업 위치가 깨진다. 떠 있는 요소의 위치는 JS 가 잡는다. 2027-01 에 다시 본다 |

## 2. 토큰 구조

```
Raw(원시)                    →  Semantic(역할)                 →  Component(컴포넌트)
src/styles/tokens/*.css         globals/_semantic.css             globals/_semantic.css
눈금 · 팔레트                     텍스트·배경·테두리 색, 글자 역할        컨트롤 높이, 버튼·행·모달 여백
테마마다 값이 바뀐다(색·그림자)        Raw 를 가리킨다                     테마와 무관
```

**2-1. 층은 셋이다.** 네 번째 층을 만들지 않는다. 모듈 안 지역 변수(`--_x`)는 층이 아니라 그 파일의 사정이다.

**2-2. 컴포넌트 CSS 는 Semantic·Component 를 부른다.** Raw 를 직접 부르는 건 그 축에 역할 층이 없을 때만이다
— 간격(`--spacing-*`) · 크기(`--size-*`) · 줄간격 · 굵기 · 그림자 · 블러 · 모션. z-index 는 토큰 이름이 이미 역할이라
층이 하나다. 축별 판정은 §3.

**2-3. 테마는 Raw 팔레트를 뒤집어서 만든다.** 팔레트 숫자는 **밝기가 아니라 바탕 → 글자 쪽 순서**다.
`--color-neutral-0` 은 라이트에서 흰색, 다크에서 검은색 — 어느 테마에서나 "바탕 끝"이다. Semantic 은 테마를
모르고 이 순서만 가리킨다(`--bg-primary: var(--color-neutral-50)`). GitHub Primer·Radix 와 같은 방식이다.
팔레트를 고정하고 Semantic 이 테마마다 다른 단계를 가리키는 방식(Material·Tailwind)도 있지만, 이미 이 방식으로
짜여 있고 바꿔도 보이는 게 없어서 바꾸지 않는다([D18](./design-system-decisions.md)).
- 테마와 상관없이 같은 색이 필요하면(이미지 위 흰 글자 등) 팔레트가 아니라 `--text-white` 같은 고정 역할을 쓴다.

**2-4. 역할 층은 필요한 축에만 만든다.** 같은 값을 여러 자리가 쓰고 **함께 바뀌어야 할 때만** 역할 이름을
만든다. 간격에는 범용 역할(`--space-card-gap` 같은 것)을 만들지 않고 Component 층에 둔다. 예외는 긴 글 지면의 리듬
`--space-section/block/divide/line` 넷 — 지면 전체가 함께 줄고 늘어야 해서 역할로 둔다.

**2-5. 이름은 「종류 → 역할 → 정도」.** 같은 종류가 사전순으로 붙는다.

| | |
|---|---|
| ✓ | `--border-color-strong` · `--control-h-md` · `--text-secondary` · `--opacity-disabled` |
| ✗ | `--border-strong-color`(종류가 뒤) · `--ui-fs-sm`(뜻 없는 접두어·임의 축약) · `--font-size-14`(값을 이름에) |

- 축약은 CSS 관례 넷만: `h`(height) · `w`(width) · `p`/`px`/`py`(padding) · `lh`(line-height). 그 밖은 풀어 쓴다(`btn` ✗ → `button`).
- 눈금 이름은 `xs · sm · md · lg · xl` 에 숫자를 붙여 늘린다(`2xl`, `3xs`). Tailwind·Primer 처럼 값을 이름에 쓰는 눈금
  (`--spacing-4`)도 업계에 흔하지만, 여기는 이미 크기 이름이라 섞지 않는다.

**2-6. 눈금은 처음부터 모든 단계를 고르게 만들어 둔다.** 쓰는 곳이 0인 단계도 지우지 않는다 — 중간이 빠지면
눈금이 고르지 않게 되고, 그 크기가 필요해지는 순간 고를 게 없어 숫자를 직접 쓰게 된다.
반 단계(`-plus`)는 새로 만들지 않는다. 지금 있는 넷(`--spacing-2xl/4xl/5xl-plus`, `--font-size-2xl-plus`)은 간격 눈금이
16단계라 크기 이름이 모자라서 생겼다. 이름만 어색하고 값은 고르므로 둔다.

**2-7. 토큰은 세 종류이고, 만드는 시점이 다르다.**

| 종류 | 예 | 만드는 시점 |
|---|---|---|
| 눈금 | `--font-size-*` · `--spacing-*` · `--size-*` · `--radius-*` · 색 팔레트 단계 | 미리 전부(2-6) |
| 역할·컴포넌트 | `--text-secondary` · `--control-h-md` · `--card-p-md` · `--border-default` · `--shadow-md` | 그 역할을 하는 자리가 생길 때 추가하고, 없어지면 지운다 |
| 편의 조합 | `--box-xs-md`(= 8px 16px) · 색마다 둔 투명도 단계 | 만들지 않는다 — 눈금 두 개를 나란히 적거나 `color-mix()` 로 |

- 값 여러 개를 묶은 토큰이 다 금지는 아니다. 테두리(두께 + 선 + 색)·그림자·글자(크기 + 줄간격 + 굵기)·전환(시간 + 곡선)은
  DTCG 규격의 묶음 타입이고, **역할 이름**이 있으면 역할 토큰이다(`--border-default`, `--shadow-md`). 금지는 역할 없이
  값만 말하는 조합이다(`--box-xs-md` 는 "왜 그 여백인지"를 말하지 않는다).
- **목표**(쓰는 곳이 없는 역할·조합 토큰 67개. 쓰는 곳 없는 눈금 단계 35개는 2-6 에 따라 남긴다)

**2-8. 토큰 원본은 CSS 다.** 값은 [토큰 표](./tokens.md)에 자동으로 나간다 — **강제**(`tokenDoc.test.ts`).
토큰을 바꾸면 `npm run tokens:doc`.

**2-9. 디자인 토큰에 `var()` 대체값을 쓰지 않는다.** 없는 토큰을 가려서 조용히 깨진다 — **강제**(stylelint).

## 3. 축별 규칙

### 3.1 색

| 층 | 토큰 |
|---|---|
| Raw | `--color-neutral-0 … 999`(바탕 → 글자 순서), `--color-accent(-dark/-light)`, 상태색(`--color-success` 등), 라벨색 |
| Semantic | `--text-*` · `--bg-*` · `--border-color-*` |

- **3.1-1. 색 값은 토큰 파일 안에만 쓴다.** 컴포넌트 CSS 는 `var()` 또는 `color-mix()` 로만 색을 만든다.
  `background`·`box-shadow`·`border`·`filter`·`mask-image` 같은 묶음 속성 안의 색도 같다.
  — **목표**(hex 17 · `rgb()/hsl()/oklch()` 60 · 지역 변수에 색 16). 지금 lint 는 `color` 등 다섯 속성의 hex 만 본다.
- **3.1-2. 반투명은 `color-mix()` 로 만든다.** 투명도 **단계** 토큰을 두지 않는다.
  ```css
  background: color-mix(in oklch, var(--color-accent) 20%, transparent);
  ```
  — **목표**(투명도 단계 토큰 82개, 269곳 사용). 지금 토큰(`--color-accent-alpha-20` 등)은 "그 색 × N%" 라
  `color-mix()` 와 결과가 같고, 색마다 13단계씩 늘어난다(Tailwind v4 도 투명도를 `color-mix()` 로 만든다).
  여러 곳이 함께 쓰는 반투명 **역할**(모달 뒤 막, 선택 배경 등)은 역할 토큰으로 두고 값만 `color-mix()` 로 정의한다.
- **3.1-3. `color-scheme` 을 테마와 같이 바꾼다.** — **목표**(`color-scheme` 0곳)
  ```css
  :root { color-scheme: light; }
  :root[data-theme="dark"] { color-scheme: dark; }
  ```
  없으면 다크 테마에서도 스크롤바·기본 폼 컨트롤·자동완성 배경이 밝게 남는다. 테마를 고르는 건 지금처럼
  `ThemeProvider` 가 `data-theme` 로 한다(OS 설정을 따르되 사용자가 바꿀 수 있다). 팔레트를 뒤집는 방식(2-3)이라
  `light-dark()` 는 필요 없다 — 테마마다 값이 다른 토큰 하나를 새로 만들 때만 쓴다.

### 3.2 간격

- 눈금: `--spacing-*` = `1 · 2 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96 · 112 · 128px`.
- **3.2-1. 여백·간격의 px/rem 숫자는 눈금 토큰으로 쓴다.** 두 값이 필요하면 토큰 두 개를 나란히 적는다. — **강제**
- **3.2-2. 반복되는 컴포넌트 종류는 Component 층의 여백 토큰을 쓴다** — `--button-p-*`, `--row-p-*`,
  `--badge-p-*`, `--modal-p-*`, `--card-p-*`, `--field-p-*`, `--cell-p-*`, `--input-p`, `--textarea-p`.
  컨트롤(버튼·입력·필드)은 3.4-3 을 따른다.
- `em`·`vw`·`vh`·`%`·`calc()`·음수는 막지 않는다 — 글자나 화면에 비례하라고 쓴 값이다.
- 지면: 좌우 `--page-px`(화면 폭에 따라 셋), 긴 글 리듬 `--panel-py` · `--space-section/block/divide/line`(2-4 예외).
- **3.2-3. `--m-sm/md/lg` 의 이름을 바꾼다.** 480px 이하에서만 정의되는 화면 비례 여백인데, 이름이 뜻 없는 축약이다(2-5).
  — **목표**(18)

### 3.3 글자

| 역할 토큰 | 크기 | 쓰는 자리 |
|---|---|---|
| `--font-size-body` | 14 | UI 본문·입력값·목록 |
| `--font-size-label` | 13 | 필드 라벨·버튼 |
| `--font-size-hint` | 12 | 보조 설명·메타·뱃지·카운터 — **가장 작은 글자** |
| `--font-size-title-sm/md/lg` | 16/18/20 | 카드·섹션·화면 제목 |
| `--font-size-body-lg/xl` | 16/18 | 긴 글 본문·리드 |
| `--font-size-2xl … 6xl` | 24 … 64 | 제목·디스플레이(단계가 곧 역할) |
| `--fluid-font-size-2xs … 10xl` | 화면 비례 | 큰 디스플레이 글자(눈금 — 쓰는 건 `3xl … 8xl`) |
| `--font-size-hero/lead/subhead/prose*` | 화면 비례 | 지면 제목·본문 |
| `--font-size-dot` | 5 | 글자가 아니라 점 장식(`aria-hidden`) — 12px 하한과 무관 |

- **3.3-1. 14px 이하 단계 이름(`sm/xs/2xs`)은 컴포넌트에서 쓰지 않고 역할 이름으로.** 12px 미만을 숫자로 쓰지 못한다. — **강제**
- **3.3-2. 가장 작은 글자는 12px 이다. 11px 단계는 두지 않는다.** — **목표**(`--font-size-micro` 를 쓰는 곳 103)
  1px 차이로 단계를 하나 더 두면 "어느 쪽을 고를지"의 기준이 흐려진다. 달력 칸처럼 조밀한 자리는 글자를 줄이지
  않고 여백·줄 수·말줄임으로 푼다. 103곳을 `--font-size-hint` 로 옮긴 뒤 `--font-size-micro` 와 눈금 `3xs`(11px)를 지운다.
- **3.3-3. 글자 크기는 토큰으로.** px/rem 숫자 금지. — **목표**(56)
- **3.3-4. 16~20px 은 단계 이름(`md`·`lg`·`xl`)이 아니라 `title-*`·`body-*` 로.** 이 구간만 같은 크기를 제목과 본문이 같이
  쓰기 때문이다. 24px 부터는 전부 제목이라 단계 이름을 그대로 쓴다. — **목표**(129)
- **3.3-5. 화면 비례 글자는 브라우저 확대(zoom)에도 커져야 한다**(WCAG 1.4.4 — 200% 까지).
  - 가운데 값에 rem 을 섞는다. 화면 단위(`vw`·`vh`)뿐이면 확대해도 안 커진다.
  - 최댓값을 최솟값의 **2.5배 이하**로 둔다. 그러면 어느 브라우저에서도 200% 확대가 보장된다. 넘으면 실제로 200% 가
    되는지 확대해 확인한다(지금 `hero` 2rem → 10rem 은 5배).
  ```css
  /* ✗ 가운데가 화면 단위뿐 — 확대해도 안 커진다 */
  font-size: clamp(2rem, min(9vw, 18vh), 10rem);
  /* ✓ rem 을 섞고, 최대 ≤ 최소 × 2.5 */
  font-size: clamp(2rem, 1.25rem + 3vw, 5rem);
  ```
  — **목표**(토큰 정의 7 — `hero/lead/subhead/prose*` · 직접 쓴 곳 151). `--fluid-font-size-*` 는 이미 rem 을 섞었다.
  간격·크기의 화면 비례 값은 해당하지 않는다.
- **3.3-6. 줄간격은 단위 없는 숫자로.** px 금지(글자 크기를 따라가지 않는다). — **목표**(21)
- **3.3-7. 줄간격 단계에서 `relaxed`(1.65)를 없앤다.** `normal`(1.6)과 0.05 차이라 구분할 이유가 없다(3.3-2 와 같은 판단).
  남는 단계: `dense` 0.9 · `fit` 1 · `compact` 1.125 · `tight` 1.25 · `snug` 1.35 · `normal` 1.6 · `loose` 1.8. — **목표**(47)
- **3.3-8. 자간은 `em` 으로.** 글자 크기를 따라가야 한다. 토큰은 `--letter-spacing-tight`(-0.03em) 하나. — **권장**
- 굵기: `--font-weight-light … black`(300 … 900).
- 글꼴: `--font-sans`(Inter) · `--font-grotesk`(Space Grotesk) · `--font-display`/`--font-serif`(Playfair) ·
  `--font-mono`(JetBrains Mono). `--font-instrument` 는 `layout.tsx` 의 next/font 변수다.
- 업계(Primer·Material)는 글자 역할을 크기·줄간격·굵기 **묶음**(`font` 단축 속성)으로 둔다. 여기는 크기만 역할이고 줄간격·굵기는
  자리마다 고른다. 묶음은 위 목표가 끝난 뒤 판단한다.

### 3.4 크기

**컨트롤 높이** — 버튼·입력·셀렉트·칩처럼 한 줄에 나란히 놓이는 것. Component 층 `--control-h-*` 하나가 정한다.

| 단계 | 2xs | xs | sm | md | lg | xl |
|---|---|---|---|---|---|---|
| 높이 | 20 | 24 | 28 | **32** | 36 | **40** |

Primer 의 컨트롤 눈금(24 · 28 · 32 · 40 · 48)과 같은 4px 간격이다.

- **3.4-1. 4px 간격 눈금 하나.** — **목표**: `xl` 을 38→40 으로(지금 Button `xl` 은 토큰 대신 40px 를 직접 씀),
  `2xl`(46) 은 컨트롤 눈금에서 뺀다.
- **3.4-2. 컨트롤 높이는 `--control-h-*` 로만.** px 숫자 금지, Raw `--size-*` 금지.
  — **목표**(단추·입력 선택자에 직접 쓴 높이 89 · `--size-*` 로 컨트롤 높이를 준 곳 3)
- **3.4-3. 컨트롤의 여백 토큰은 좌우만 정한다.** 높이는 3.4-2 가 정하고, 세로 여백 + 글자 크기로 높이를 만들지 않는다.
  둘이 같이 높이를 정하면 같은 `md` 가 글꼴에 따라 26px 도 32px 도 된다. 여러 줄인 `--textarea-p` 는 그대로.
  — **목표**(`--button-p-*` · `--input-p` · `--field-p-*` 를 쓰는 곳 57)
- **3.4-4. 누르는 것은 24×24 이상.** WCAG 2.2(2.5.8, AA). `2xs`(20) 는 누르지 않는 것(뱃지·표시)에만 쓰거나,
  누르는 것이면 `::before` 로 누르는 영역을 24 이상으로 넓힌다. 이웃과 24px 원이 겹치지 않을 만큼 떨어져 있으면
  작아도 된다(WCAG 의 간격 예외). — **목표**(`2xs` 를 쓰는 14곳 확인)
  손가락 입력(`@media (pointer: coarse)`)에서는 누르는 영역을 44 이상으로 넓힌다(Apple 44pt · Material 48dp · Primer 44). — **권장**
- **3.4-5. 같은 이름 = 같은 높이.** 공용 컴포넌트의 `size` prop 은 위 눈금 이름을 그대로 따른다
  (`size="sm"` 이면 어느 컴포넌트든 28). — **목표**: CloseButton 이 한 칸 밀려 있다(xs 20 · sm 24 · lg 38).

**떠 있는 단추** — 이미지 뷰어·배너 넘김처럼 화면 위에 떠 있는 원형 단추. 줄에 나란히 놓이지 않으므로
컨트롤 눈금이 아니라 Component 토큰 `--float-button-sm`(40) · `--float-button-md`(48) 을 쓴다. 지금 38 · 46 을 4px 눈금에 맞춘다.
— **목표**(새 토큰)

**그 밖의 사각형** — 아이콘·아바타·썸네일은 Raw `--size-*`(4 … 112px). `md` 38 · `lg` 46 은 옛 컨트롤 높이가 남은 값이라
눈금 사이가 고르지 않다(24 → 32 → 38 → 46 → 56). 떠 있는 단추를 옮긴 뒤 4px 눈금으로 맞춘다. — **목표**(`--size-md` 4곳)

**레이아웃 치수** — 내용 폭은 `--width-*`(180 … 2400px), 골격 치수는 `--header-height` · `--side-nav-width` 처럼
이름이 곧 자리다. 골격 치수는 성격상 Component 층인데 지금 Raw 파일(`_sizing.css`)에 있다. — **권장**(옮기기)

### 3.5 모서리

| 층 | 토큰 |
|---|---|
| 눈금 | `--radius-2xs` 2 · `xs` 4 · `sm` 6 · `md` 8 · `lg` 12 · `xl` 16 · `2xl` 24 · `circle` 50% · `capsule` 9999px |
| 역할 | 아래 넷 — 이행 11단계에서 추가 |

| 역할 토큰 | 값 | 자리 |
|---|---|---|
| `--radius-control` | capsule | 버튼·칩·뱃지·입력·hover/선택 배경 하이라이트 |
| `--radius-surface` | 2xl(24) | 카드·패널·모달처럼 면이 있는 것 |
| `--radius-round` | circle | 아바타·아이콘 버튼 등 정원 |
| `--radius-mark` | xs(4) | 각진 것 자체가 의미인 자리 — 체크박스·다중선택 마커(단일은 원, 다중은 네모)·컬러피커 SV 사각형·`shape="square"` |

- **3.5-1. 컴포넌트는 역할 토큰만 쓴다.** 눈금(`--radius-2xl` 등)은 역할 토큰을 정의할 때만 쓴다. 글자 크기(§3.3)와 같은 구조다.
  — **목표**(눈금 이름을 직접 쓴 곳 1176 — 이름만 바뀌고 보이는 건 그대로 · lint 를 끄고 눈금을 직접 쓴 예외 19)
  같은 성격의 카드가 6px 과 12px 로 갈리는 걸 막는 건 "눈금이 셋뿐"이 아니라 "고를 수 있는 역할이 넷뿐"이다.
  지금 lint 는 `capsule`·`circle`·`2xl` 밖의 눈금 이름을 막는다. 역할 토큰을 만들 때 `_semantic.css` 의 정의는 lint 에서 뺀다.
- **3.5-2. 모서리는 토큰으로.** `50%`·`9999px` 은 **강제**로 막는다. `2px` 같은 숫자는 **목표**(21). 각지게 하려면 `0`.
- **3.5-3. 안쪽 요소의 모서리는 바깥 모서리 − 사이 여백**(동심원)으로 맞춘다. 같은 값을 겹쳐 쓰면 안쪽이 더 둥글어 보인다.
  이때는 눈금에서 가장 가까운 단계를 쓴다(예: 바깥 24 · 여백 8 → 안쪽 16 = `xl`. 바깥 24 · 여백 10 → 14 는 눈금에 없으니 가까운 `xl` 16). — **권장**

### 3.6 테두리·그림자·블러·투명도

- 테두리 두께는 `--border-width-thin` 1 · `thick` 2 · `thicker` 3 · `thickest` 4. 테두리 묶음은 `--border-*`(2-7 의 묶음 타입).
  숫자로 쓴 테두리 — **목표**(46). `--border-width-default`(1.5px)는 쓰는 곳이 없고, 1px 화면에서 흐리게 그려져 지운다(이행 2단계).
- 그림자는 `--shadow-*`(다크에서 더 진하다). 그림자 값을 직접 쓰지 않는다 — **목표**(29)
- 블러는 `--blur-*`(`blur()` 값), 유리 효과는 `--blur-glass`. `backdrop-filter` 에 접두어를 붙이지 않는다(§8).
- **3.6-1. 비활성 상태의 투명도는 `--opacity-disabled` 하나로.** 지금 비활성 선택자 47곳이 12가지 값(0.25 … 0.85, 가장 많은 건
  0.5)을 쓴다 — 2-4 의 "함께 바뀌어야 하는 같은 역할"이다. 값은 이행 때 미리보기로 정한다. — **목표**(47)
  그 밖의 `opacity` 는 장식이라 토큰을 두지 않는다.

### 3.7 모션

| 토큰 | 값 | 자리 |
|---|---|---|
| `--duration-instant` | 100ms | 즉각 피드백(토글) |
| `--duration-fast` | 150ms | 호버 |
| `--duration-base` | 300ms | 기본 전환 |
| `--duration-moderate` | 350ms | 없앤다(3.7-3) |
| `--duration-slow` | 500ms | 패널 슬라이드 |
| `--duration-slower` | 800ms | 페이지 전환 |
| `--duration-slowest` | 1.5s | 장식용 긴 움직임 |
| `--delay-short/base/long` | 100/200/350ms | 순차 등장 |
| `--ease-material` | `cubic-bezier(.4,0,.2,1)` | 범용 |
| `--ease-out-expo` | `cubic-bezier(.16,1,.3,1)` | 등장 |
| `--ease-bounce` | `cubic-bezier(.34,1.56,.64,1)` | 탄성 |
| `--ease-in-out` | `cubic-bezier(.25,.1,.25,1)` | 없앤다(3.7-3) |

- **3.7-1. 시간·곡선은 토큰으로.** `transition`·`animation` 에 `0.3s` 같은 숫자를 쓰지 않는다. — **목표**(451)
- **3.7-2. 움직임 줄이기 설정은 토큰에서 한 번에 처리한다.** `prefers-reduced-motion: reduce` 이면 `:root` 에서
  `--duration-*` 을 `0.01ms` 로 바꾼다(0 이면 `transitionend` 가 안 와서 그걸 기다리는 코드가 멈춘다). 시간 토큰을 쓴 곳은
  따로 처리하지 않아도 된다. 큰 이동·시차 효과는 모듈에서 따로 끄고, 대신 투명도 전환은 남겨도 된다. — **목표**
- **3.7-3. 구분되지 않는 단계와 이름이 틀린 토큰을 없앤다.** `moderate`(350)는 `base`(300)와 50ms 차이라 고르는
  기준이 없다 — `base` 로. `--ease-in-out` 은 이름과 달리 CSS `ease` 곡선이다 — `--ease-material` 로. — **목표**(31 + 3)
- **3.7-4. 테마 전환은 View Transitions 로.** — **목표**
  지금은 테마를 바꾸는 350ms 동안 `html[data-theme-transitioning] *` 이 모든 요소에 색 transition 을 건다. 2026-09-26 전에는
  이 규칙이 `data-theme-ready` 로 **항상** 걸려 있어서 컴포넌트의 transition 을 덮었고, 그걸 이기려고 붙인 특이도 보정·주석과
  `!important` 가 남아 있다(CSS 80줄 · `!important` transition 6 · 그 규칙을 설명하는 화면 문구 5). 지금 규칙에서는 대부분
  필요 없다. `document.startViewTransition` 으로 화면을 한 번에 바꾸고, 지원하지 않거나 움직임 줄이기 설정이면 즉시 바꾼다.

### 3.8 쌓임

- **3.8-1. 화면 위에 뜨는 것은 top layer 에 올린다.** 모달은 `<dialog>` + `showModal()`, 팝오버·툴팁·셀렉트 목록·
  날짜/색/이모지 선택기는 Popover API(`popover` 속성). top layer 는 z-index 와 무관하게 맨 위라
  "모달 안의 셀렉트가 모달 뒤로 숨는" 문제가 구조적으로 없다. — **목표**(`createPortal` 을 쓰는 파일 52)
  - top layer 는 z-index 를 이긴다. 그래서 모달보다 **위에** 있어야 하는 것(커스텀 커서·로딩 화면·페이지 전환)도 top layer 에
    올려야 한다. 나중에 연 것이 위로 가므로, 커서는 `popover="manual"` 로 두고 모달이 열릴 때마다 다시 연다.
  - 위치는 아직 JS 가 잡는다(1-1, anchor positioning 은 아직 안 씀).
- **3.8-2. 페이지에 고정된 UI 의 층은 `--z-*` 토큰으로.**

| 토큰 | 값 | 자리 | 3.8-1 뒤 |
|---|---|---|---|
| `--z-below` | -1 | 배경(영상 배경 등) | 남김 |
| `--z-content` | 10 | 페이지 콘텐츠 | 남김 |
| `--z-nav` | 100 | 고정 내비게이션 | 남김 |
| `--z-float` | 200 | 내비 위 고정 UI | 남김 |

| `--z-modal` · `overlay` · `fullscreen` | 8000 · 9000 · 9500 | 모달·드로어·에디터 전체화면 | 지움(`<dialog>`) |
| `--z-loading` · `top` · `cursor` | 9800 · 10000 · 10100 | 로딩 화면·페이지 전환·커스텀 커서 | 지움(top layer, 위 참고) |

### 3.9 레이아웃·반응형

- **3.9-1. 작은 화면이 기본이다.** 큰 화면에서 덧붙인다(`min-width`). — **목표**(`max-width` 미디어 쿼리 210)
- **3.9-2. 미디어 쿼리는 범위 문법으로, 기준값은 셋.** `var()` 는 미디어 쿼리에 못 쓰므로 값을 직접 적는다.
  ```css
  @media (width >= 480px)  { … }  /* 큰 휴대폰 */
  @media (width >= 768px)  { … }  /* 태블릿 */
  @media (width >= 1024px) { … }  /* 데스크톱 */
  ```
  지금 쓰는 값: 768(95) · 1024/1025(100) · 480(23) · 640(19) · 그 밖 900·560·992 등(16). 1024 와 1025 가 짝으로 있는 건
  `max-width: 1024px` / `min-width: 1025px` 로 경계를 1px 띄워야 했기 때문이다 — 범위 문법(`<` · `>=`)은 그럴 필요가 없다.
  640 과 그 밖의 값은 이행 때 가까운 기준으로 옮기고 화면별로 확인한다. — **목표**
  `_sizing.css` 의 `--mobile` · `--tablet` · `--pc` 는 CSS·JS 어디서도 읽지 않는다(이행 2단계에서 지움).
- **3.9-3. 컴포넌트의 반응형은 container query 로.** 화면 폭이 아니라 놓인 자리의 폭을 따른다. 미디어 쿼리는
  페이지 골격에만. — **권장**(지금 6곳)
- **3.9-4. 등분 grid 는 `--grid-cols-*`**(`repeat(N, minmax(0, 1fr))`). `1fr` 만 쓰면 자식이 트랙을 밀어 넘친다.
  카드·타일 grid 는 `repeat(auto-fit, minmax(min(100%, 220px), 1fr))`. — **권장**
- 재사용 레이아웃에 `id` 선택자를 쓰지 않는다(페이지 골격 하나만 예외).

## 4. 우선순위와 순서 — cascade layer

**4-1. 전역 CSS 는 층에 넣고, 컴포넌트 CSS(Modules)는 층 밖에 둔다.** — **목표**(`@layer` 0곳)

| 층 | 내용 |
|---|---|
| `reset` | 브라우저 기본값 정리(`sanitize.css`) |
| `vendor` | 서드파티 CSS(KaTeX · React Flow · Pretendard)와 그 덮어쓰기 |
| `tokens` | `tokens/*`, `_semantic.css` |
| `base` | 요소 기본 스타일, 스크롤 |
| `utilities` | `.sr-only` 같은 전역 클래스 |

층 밖의 스타일은 **어느 층보다도 이긴다** — 특이도와 상관없다. 그래서 전역 규칙을 이기려고 클래스를 두 번
적거나(`.x.x`) `!important` 를 붙이던 일이 없어진다. `!important` 는 층에서 거꾸로 동작하므로(앞 층이 이긴다)
전역 CSS 에 쓰지 않는다.

**4-2. 층 순서 선언은 다른 어떤 CSS 보다 먼저 나와야 한다.** 층 순서는 그 층 이름이 **처음 나온 순서**로 정해진다.
Turbopack 은 `@import` 로 가져온 CSS 를 그 파일의 다른 내용보다 앞에 놓는다(개발 서버에서 확인 — 아래 예에서
`@layer vendor { … }` 가 순서 선언보다 먼저 나온다). 그래서 순서 선언을 CSS 파일 안에 두면 `vendor` 가 맨 앞 층이 된다.
순서 선언은 루트 `layout.tsx` 의 `<head>` 맨 앞에 인라인 `<style>` 로 둔다.
```tsx
<style>{"@layer reset, vendor, tokens, base, utilities;"}</style>
```

**4-3. 서드파티 CSS 는 JS 에서 바로 import 하지 않고, 층을 단 CSS 파일을 거친다.** JS 에서 바로 import 한 CSS 는 층 밖이라
모든 전역 규칙과 `vendor` 층의 덮어쓰기를 이긴다. 지금 KaTeX(8곳) · React Flow(4곳) · Pretendard(1곳)가 그렇다.
```css
/* src/styles/vendor/katex.css — 쓰는 화면에서 이 파일을 import 한다(코드 분할은 그대로) */
@import "katex/dist/katex.min.css" layer(vendor);
```
Turbopack 이 이 형태를 `@layer vendor { … }` 로 감싸는 것을 확인했다(2026-10-02, 개발 서버).

**4-4. 컴포넌트 CSS 끼리는 층이 해결하지 못한다.** 두 모듈의 단일 클래스가 한 요소에서 겨루면 승자는 번들
순서인데, 개발 서버와 배포 빌드에서 순서가 다르다(#632). 그래서:

- 다른 파일의 클래스를 `composes` 로 가져오지 않는다. 필요한 선언은 그 모듈에 쓴다. — **권장**
- 같은 파일 안 `composes` 는 한 단계까지(Turbopack 이 두 단계째를 안 붙인다).
- `className` 을 받는 공용 컴포넌트는 이길 쪽을 정해 둔다 — 이겨야 하면 `.x.x`(0,2,0), 져야 하면 `:where(.x)`(0,0,0).

## 5. 컴포넌트

**누르는 것은 `Button` 아니면 `Pressable`.** 맨 `<button>` 은 쓰지 않는다.

| | 주는 것 | 언제 |
|---|---|---|
| `Pressable` | 동작만 — `type="button"`·사운드·disabled·누를 때 축소·UA 스타일 초기화 | 생김새가 그 자리 사정을 따르는 것 |
| `Button` | 동작 + 생김새(`variant` `size` `tone` `shape`) | 버튼처럼 생긴 버튼 |

MUI `ButtonBase`, React Aria `useButton` 과 같은 분리다. 생김새를 `Button` 에 다 담으려고 prop 을 늘리지 않는다.

**인라인 `style` 은 JS 가 계산한 값에만** — 위치·크기·진행률·드래그 좌표처럼 렌더마다 바뀌는 값. 고정된 생김새는 CSS 에 쓴다.
넘길 때는 가능하면 CSS 변수로 넘겨 CSS 가 쓰게 한다: `style={{ "--_x": `${x}px` }}`. — **권장**
지금 `style={{…}}` 는 946곳이고 대부분 동적 값이라, lint 로는 고정값만 골라 막을 수 없다. eslint 가 막는 건 인라인 style·
문자열 안의 **14px 이하 글자 크기 눈금 이름과 모서리 눈금 이름**뿐이다(§9).

## 6. 클래스 이름

- CSS Modules 라 이름은 해시된다. **camelCase**, BEM(`__`·`--`) 쓰지 않는다. 계층은 nesting·자식 선택자로.
- 이름은 생김새가 아니라 역할로: 루트 `.card` `.panel` · 래퍼 `.row` `.group` · 글 `.title` `.meta`.
- **상태는 그 상태를 뜻하는 속성으로 고른다.** 접근성 속성이 있으면 그것을(`[aria-expanded="true"]` · `[aria-selected]` ·
  `[aria-current]` · `:disabled`), 없으면 `data-*`(`[data-state="open"]`)를. 화면 낭독기가 읽는 상태와 보이는 상태가 어긋나지
  않는다(Radix·React Aria 방식). 상태 클래스(`.isActive`)는 그런 속성이 없을 때만. — **권장**
- JS 로 상태 클래스를 붙일 때는 해시된 이름을 쓴다: `el.classList.toggle(styles.isActive, on)`.

## 7. 접근성

- **`:focus-visible` 링을 없애지 않는다.** `outline: none` 을 쓰면 같은 규칙에 대신할 링을 준다. — **목표**(`outline: none` 69곳 확인)
- 누르는 것 24×24 이상(3.4-4), 글자 확대(3.3-5), 움직임 줄이기(3.7-2), 다크 테마의 기본 컨트롤(3.1-3), 상태 속성(§6).
- 화면에 안 보이고 읽어 주기만 할 글은 `.sr-only`.

## 8. 쓰지 않는 것

| | 이유 | 상태 |
|---|---|---|
| Tailwind·유틸리티 클래스 | 두 방식이 섞이면 같은 레이아웃이 두 모양으로 갈린다 | 강제(의존성 없음) |
| 런타임 CSS-in-JS | RSC 와 안 맞고 런타임 비용 | 강제(의존성 없음) |
| 디자인 토큰의 `var()` 대체값 | 없는 토큰을 가린다 | 강제 |
| `-webkit-backdrop-filter` | 빌드(Lightning CSS)가 접두어·표준을 같은 속성으로 보고 **뒤에 적힌 하나만 남긴다.** 흔한 순서(표준 → 접두어)로 쓰면 접두어만 남아 크롬에서 블러가 사라진다. 지원 범위(Safari 26.5+)는 접두어 없이 되므로 필요도 없다 | 강제 |
| `id` 선택자로 재사용 레이아웃 | 특이도가 튀고 재사용이 안 된다 | 권장 |
