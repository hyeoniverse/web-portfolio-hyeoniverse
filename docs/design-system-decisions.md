# 디자인 시스템 결정 기록

> [명세](./design-system.md)의 규칙을 **왜** 그렇게 정했는지와 그동안의 이력. 규칙 자체는 명세에만 적는다.
> 새 결정은 맨 아래에 번호를 이어 붙인다. 뒤집힌 결정은 지우지 않고 "→ D번호로 바뀜"을 단다.

---

### D1. CSS Modules + 토큰 하나로 간다 (Tailwind 를 되돌림)

Tailwind 를 한 번 들였다가 같은 flex 행이 어디는 `tw:flex`, 어디는 `styles.row` 인 상태가 됐다. 두 방식이
반반 섞이면 어느 쪽이 기준인지 아무도 모른다. 이 사이트는 커스텀 애니메이션·GSAP·Three.js·정교한 CSS 효과가
핵심이라 컴포넌트마다 맞춘 CSS 가 유리하고, 토큰 체계도 이미 있었다. RSC 에 안전하고 런타임 비용이 없다는 것도
CSS Modules 쪽 이점이다.

### D2. 토큰 층은 셋

모듈 안의 `--_*` 를 네 번째 층으로 적어 뒀는데 실제로 쓰는 컴포넌트가 0곳이라 뺐다. Material(ref → sys → comp),
Spectrum(global → alias → component)도 세 층이다.

### D3. 간격에 조합 토큰을 두지 않는다

`--box-xs-md` 같은 여백 조합 토큰이 119개까지 불었고 84개가 안 쓰였다. 65개로 줄여도 근본 문제는 남았다 —
`--box-2xs-sm` 은 "4px 12px" 라는 값만 말하고 **왜 그 여백인지**는 말하지 않는다. Carbon·Atlassian·Polaris
어디에도 조합 토큰은 없다. 눈금 두 개를 나란히 적고, 반복되는 컴포넌트 종류에는 역할 토큰(`--card-p-md` 등)을 준다.
간격 눈금 사이 값(3px·6px 등) 106곳은 가까운 눈금으로 붙였다(최대 4px 차이).

### D4. 컴포넌트 여백 역할 토큰을 만드는 법

뱃지 118곳이 29가지 여백을 썼다. 이름만 통일하면 숫자는 안 준다. 등급을 글자 크기로 나눴더니(12px → md,
13px → lg) `StatusBadge` 가 넓어져 관리자 표의 Edit 단추를 침범했다 — 같은 13px 이라도 표 안 상태 뱃지는
조밀해야 하고 누르는 태그 필터는 넉넉해야 한다. 그래서 **각 자리에서 가장 가까운 등급**으로 붙였다. 이동이 가장
적고, 이미 맞는 자리는 이름만 바뀐다. 4px 넘게 떨어진 곳은 의도로 보고 두었다. 목록 행도 33종 → 3종. 가로
여백이 0인 행은 부모가 좌우를 주므로 제외했다. 모달·카드·입력 필드도 같은 방법.

### D5. 컨트롤 높이를 하나로

`--button-h-*`(20/24/38/46), `--control-h-*`(24/28/32/36), `_sizing.css` 주석의 "계층"(24/32/38/46)이 같은
"컨트롤 높이"를 다르게 말했다. 같은 `size="md"` 가 자리에 따라 32px 이기도 38px 이기도 했다. 공용 Button·Input 이
실제로 쓰던 `--control-h-*` 를 남기고 나머지를 흡수했다(렌더는 그대로). 흡수하면서 2xs·xl·2xl 이 들어와 간격이
고르지 않게 됐다 → D12 에서 정리.

### D6. 모서리는 셋 → D16 으로 바뀜

2px ~ 42px 눈금이 열세 개 있었고, 같은 성격의 카드가 6px 과 12px 로 갈렸다. 쓰는 곳이 0인 단계는 지우고,
컴포넌트가 고르는 건 capsule · circle · 2xl 셋으로 줄였다.

### D7. 글자 크기에 역할 이름

14px 이하 네 단계는 원래 그 역할(본문·라벨·힌트·마이크로)을 위해 있던 값이라 1:1 로 역할 이름을 줬다.
16·18·20px 에만 `title-*`·`body-*` 이름을 붙인 건, 이 구간에서만 같은 크기를 제목과 본문이 같이 쓰기 때문이다.
24px 부터는 전부 제목·디스플레이라 단계 이름이 곧 역할이다.

### D8. 지운 토큰들

`--fluid-spacing-*` 11개(사용 0), `--breakpoint-*` 7개(사용 0 — 미디어 쿼리는 `var()` 를 못 받는다).

### D9. Button 과 Pressable 을 나눔

생김새를 통일하면 안 되는 자리가 많다 — 절대위치 클릭 영역, 부모 글꼴을 물려받는 페이지 번호, 필터 행 높이에 맞춘
탭. 그 자리들이 놓치던 건 생김새가 아니라 **동작**이었다(사운드 없음, `type` 없어 폼 안에서 제출 — 63곳,
disabled 제각각). 동작만 `Pressable` 로 떼었다. `react/button-has-type` 은 셋 중 하나만 막는다.

### D10. 다른 파일 클래스를 `composes` 하지 않는다 (#632)

두 모듈의 단일 클래스가 한 요소에서 겨루면 승자는 소스 순서다. 개발 서버는 import 순서대로 한 청크에 담고,
배포 빌드는 Turbopack 이 청크를 나눈 뒤 `experimental.inlineCss` 로 다시 싣는다 — 같은 코드가 개발과 배포에서
다르게 보였다. 같은 파일 안 `composes` 도 두 단계째는 Turbopack 이 안 붙인다.

### D11. 2026-10-01 — 명세를 다시 씀

이전 문서는 방향(3층·조합 금지·역할 이름·lint 강제)은 업계 관례와 맞았지만, 실무 기준으로 낡거나 틀린 판단이
있었고, "막는다"고 적은 규칙 상당수를 lint 가 실제로 막지 않았다. 다시 쓰면서 바꾼 것:

| | 이전 | 지금 | 근거 |
|---|---|---|---|
| 문서 형태 | 규칙·이유·이력·값이 한 파일 | 명세 · 결정 기록 · 토큰 표(자동 생성) | 손으로 옮긴 값이 어긋났다(모션 시간 문서 250/400/600ms, 실제 300/500/800ms) |
| 규칙 상태 | 전부 "금지" | 강제 / 목표(남은 수) / 권장 | lint 는 색 다섯 속성의 hex 만 봤고 z-index·모션·숫자 모서리는 막지 않았다 |
| 테마 | Raw 팔레트를 다크에서 뒤집음 | Raw 는 고정, Semantic 이 `light-dark()` 로 바꿈 · `color-scheme` | 팔레트 이름이 테마마다 다른 색을 뜻했다. `color-scheme` 이 없어 다크에서도 스크롤바·폼이 밝았다 |
| 반투명 | 투명도별 토큰 82개 | `color-mix()` | `color-mix()` 도 159곳이 이미 써서 방식이 둘이었다 |
| 유동 글자 | 가운데 값이 vw 뿐 | 가운데에 rem 섞기 | 화면 단위뿐이면 브라우저 확대에 안 커진다(WCAG 1.4.4) |
| 테마 전환 | 전역 `*` transition | View Transitions | 전역 transition 이 컴포넌트 transition 을 덮어 특이도 보정·`!important` 가 퍼졌다 |
| 우선순위 | 특이도 올리기(`.x.x`, `!important`) | `@layer` 로 전역을 층에, 모듈은 층 밖 | 문서는 `@layer` 를 "적극 사용"이라 했지만 0곳이었다 |
| 겹침 | z-index 토큰 + 포털 | `<dialog>`·Popover API(top layer) | 지원 범위(Safari 18+)에서 쓸 수 있고 z-index 경쟁이 없다 |
| 컨트롤 높이 | 20/24/28/32/36/38/46 | 20 … 40, 4px 간격 · 떠 있는 단추 분리 | 간격이 고르지 않았고 Button `xl` 은 토큰과 다른 40px 를 썼다 |
| 누르는 크기 | "최소 크기 유지" | 24×24(WCAG 2.2 2.5.8) | 눈금에 20px 컨트롤이 있었다 |
| 반응형 | 큰 화면 기준 `max-width` | 작은 화면 기준 · 범위 문법 · 컴포넌트는 container query | 현행 관례 |
| `-webkit-backdrop-filter` | "크롬 파서가 꼬여서" 금지 | 빌드가 표준 선언을 지워서 금지 → D17 | 크롬은 모르는 접두어를 무시할 뿐이다. 이유가 틀렸다 |

### D13. 2026-10-02 — 눈금은 미리 전부, 지우는 건 역할·조합 토큰만

D11 의 2-7 은 "쓰는 순간 추가하고, 안 쓰게 되면 지운다"를 모든 토큰에 거는 것처럼 읽혔다. 눈금(`--font-size-*`
`--spacing-*` 등)은 단계가 고르게 다 있어야 골라 쓸 수 있어서 쓰는 곳이 0이어도 남긴다(2-6). "쓸 때 추가·안 쓰면
삭제"는 역할·컴포넌트 토큰에만, 조합 토큰은 아예 만들지 않는 것으로 범위를 나눴다. 안 쓰는 토큰 102개 중
눈금 단계 35개는 남기고 67개만 정리 대상이다.

### D14. 2026-10-02 — 11px(`micro`)과 12px(`hint`)을 둘 다 둔다 → D15 로 바뀜

1px 차이지만 나눈다. 조밀한 자리(달력 칸·표 안 뱃지·카운터)에서는 8% 차이가 줄바꿈을 가른다. Apple(Caption 2 11 /
Caption 1 12)·Material(label-small 11 / body-small 12)도 같은 둘을 둔다.
다만 이전 문서의 근거 "못 읽어도 되는 것"은 틀렸다 — 실제로 103곳 중 달력 요일·일정 이름·입력 글자 수처럼 읽어야
하는 자리가 많다. 기준을 "문장이냐 짧은 라벨이냐"로 바꿨다: 문장은 12px 이상, 11px 은 숫자·카운터·요일 같은 짧은 라벨만.
"12px 하한"이라면서 11px 토큰이 있던 모순도 "문장의 하한 12 / 숫자로 쓸 수 있는 하한 12, 11 은 토큰으로만"으로 정리했다.

### D15. 2026-10-02 — 11px 단계를 없앤다 (D14 를 뒤집음)

D14 는 조밀한 자리의 1px 을 근거로 11·12 를 둘 다 뒀지만, 1px 차이의 두 단계는 고르는 기준이 "문장이냐 라벨이냐"
같은 해석에 기대게 되고 실제로도 섞여 쓰였다(달력 요일·일정 이름 같은 읽어야 하는 글자에 11px). 가장 작은 글자를
12px 하나로 정하고, 조밀한 자리는 글자 크기가 아니라 여백·줄 수·말줄임으로 푼다.
`--font-size-micro` 를 쓰는 103곳을 `--font-size-hint` 로 옮긴 뒤 토큰과 눈금 `3xs`(11px)를 지운다(이행 8단계).

### D16. 2026-10-02 — 모서리도 눈금 + 역할로 (D6 을 바꿈)

D6 은 "고르는 건 capsule·circle·2xl 셋"을 눈금 이름으로 정하고 쓰지 않는 단계(`lg` 12 · `xl` 16 등)를 지웠다.
그러자 눈금이 2·4·6·8 다음 24 로 건너뛰어 2-6(눈금은 미리 전부)과 어긋났고, 각진 것이 의미인 자리 19곳은 규칙 위반 주석을
달고 눈금을 직접 써야 했으며, "안쪽 = 바깥 − 여백" 권장은 정작 그 사이 값을 쓰지 못했다.
"셋만"은 눈금 규칙이 아니라 역할 규칙이었다. 글자 크기처럼 눈금은 빠짐없이 두고(`lg`·`xl` 을 되살린다), 컴포넌트는
역할 토큰 넷(`control`·`surface`·`round`·`mark`)만 쓴다. 지금 눈금 이름을 직접 쓴 1176곳은 이름만 바꾸면 되고 보이는 건 그대로다.

### D17. 2026-10-02 — `-webkit-backdrop-filter` 를 쓰지 않는 진짜 이유

접두어를 붙였을 때 크롬에서 블러가 사라지는 일이 두 번 있었다(5월 토스트·홈 CTA, `bc9af356` 에서 일괄 제거).
이전 문서는 "크롬 파서가 꼬인다"고 적었지만, 크롬은 모르는 접두어 선언을 무시할 뿐이다. 원인은 빌드다.
Next(Turbopack)가 쓰는 Lightning CSS(1.33)는 `backdrop-filter` 와 `-webkit-backdrop-filter` 를 같은 속성으로 보고
**뒤에 적힌 하나만 남긴다.**

| 원래 CSS | 빌드 결과 |
|---|---|
| `backdrop-filter: blur(16px); -webkit-backdrop-filter: blur(16px)` | `-webkit-backdrop-filter: blur(16px)` 만 — 크롬은 블러 없음 |
| `-webkit-backdrop-filter: …; backdrop-filter: …` | `backdrop-filter` 만 — 정상 |

지원 범위(Safari 18+)는 접두어 없이 되므로 붙일 이유도 없다. stylelint `property-disallowed-list` 로 막는다.
