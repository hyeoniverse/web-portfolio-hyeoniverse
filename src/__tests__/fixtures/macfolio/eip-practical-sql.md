> [!WARNING] NULL과 3값 논리
> SQL의 조건식은 TRUE, FALSE, UNKNOWN 세 값을 가진다. NULL과 비교하면 UNKNOWN이 되고, `TRUE AND UNKNOWN`은 UNKNOWN, `TRUE OR UNKNOWN`은 TRUE, `NOT UNKNOWN`은 UNKNOWN이다. WHERE와 HAVING은 TRUE인 행만 통과시킨다.

### ORDER BY

```sql
SELECT 학번, 과목코드, 점수 FROM 수강 ORDER BY 과목코드 ASC, 점수 DESC;
```

| 학번 | 과목코드 | 점수 |
| ---- | -------- | ---- |
| 2401 | DB101    | 95   |
| 2403 | DB101    | 85   |
| 2405 | DB101    | 78   |
| 2402 | DB101    | 72   |
| 2405 | NW201    | 90   |
| 2401 | NW201    | 80   |
| 2406 | NW201    | 55   |
| 2402 | NW201    | NULL |
| 2403 | SE301    | 91   |
| 2401 | SE301    | 88   |
| 2405 | SE301    | 83   |
| 2404 | SE301    | 67   |

첫 번째 기준(과목코드 오름차순)으로 정렬하고, 과목코드가 같은 행끼리만 두 번째 기준(점수 내림차순)을 적용한다. ASC는 생략할 수 있다. NULL의 정렬 위치는 DBMS마다 다르다. SQLite와 MySQL은 NULL을 가장 작은 값으로 보아 내림차순에서 맨 뒤에 두고, Oracle과 PostgreSQL은 NULL을 가장 큰 값으로 보아 내림차순에서 맨 앞에 둔다. 표준 SQL의 `NULLS FIRST`, `NULLS LAST`로 위치를 직접 지정할 수 있다.

## 집계 함수와 GROUP BY

### 집계 함수와 NULL

| 함수         | 하는 일                       | NULL 처리      |
| ------------ | ----------------------------- | -------------- |
| `COUNT(*)`   | 행 수                         | NULL 행도 집계 |
| `COUNT(열)`  | 그 열이 NULL이 아닌 행 수     | NULL 제외      |
| `SUM(열)`    | 합계                          | NULL 제외      |
| `AVG(열)`    | 평균 (합계 ÷ NULL 아닌 행 수) | NULL 제외      |
| `MAX`, `MIN` | 최댓값, 최솟값                | NULL 제외      |

```sql
SELECT COUNT(*) AS 전체행, COUNT(점수) AS 점수있는행, SUM(점수) AS 합계,
       AVG(점수) AS 평균, MAX(점수) AS 최고, MIN(점수) AS 최저
FROM 수강;
```

| 전체행 | 점수있는행 | 합계 | 평균              | 최고 | 최저 |
| ------ | ---------- | ---- | ----------------- | ---- | ---- |
| 12     | 11         | 884  | 80.36363636363636 | 95   | 55   |

평균은 884 ÷ 12가 아니라 884 ÷ 11이다. AVG는 NULL인 행을 분모에서도 뺀다. 이도윤(2402)의 평균을 구하면 이 차이가 분명해진다.

```sql
SELECT AVG(점수) FROM 수강 WHERE 학번 = 2402;
```

| AVG(점수) |
| --------- |
| 72.0      |

이도윤의 수강 행은 DB101(72)과 NW201(NULL) 2행이지만 평균은 72 ÷ 1 = 72.0이다. NULL을 0점으로 처리하려면 `AVG(COALESCE(점수, 0))`처럼 NULL을 다른 값으로 바꾸는 함수를 써야 한다.

### GROUP BY와 HAVING

GROUP BY는 지정한 열의 값이 같은 행끼리 묶어 그룹마다 집계 함수를 적용한다. HAVING은 그룹을 만든 뒤 그룹 단위로 조건을 건다.

```sql
SELECT 과목코드, COUNT(*) AS 수강인원, ROUND(AVG(점수),1) AS 평균
FROM 수강 GROUP BY 과목코드;
```

| 과목코드 | 수강인원 | 평균 |
| -------- | -------- | ---- |
| DB101    | 4        | 82.5 |
| NW201    | 4        | 75.0 |
| SE301    | 4        | 82.3 |

NW201의 평균은 (80 + 55 + 90) ÷ 3 = 75.0이다. 수강인원은 `COUNT(*)`라서 NULL 행을 포함한 4다.

```sql
SELECT 학번, COUNT(*) AS 과목수, SUM(점수) AS 총점
FROM 수강 GROUP BY 학번 HAVING COUNT(*) >= 2 ORDER BY 총점 DESC;
```

| 학번 | 과목수 | 총점 |
| ---- | ------ | ---- |
| 2401 | 3      | 263  |
| 2405 | 3      | 251  |
| 2403 | 2      | 176  |
| 2402 | 2      | 72   |

WHERE와 HAVING을 함께 쓰면 WHERE가 먼저 행을 거르고, 남은 행으로 그룹을 만든 뒤 HAVING이 그룹을 거른다.

```sql
SELECT 과목코드, ROUND(AVG(점수),1) AS 평균
FROM 수강 WHERE 점수 >= 70 GROUP BY 과목코드 HAVING AVG(점수) >= 85;
```

| 과목코드 | 평균 |
| -------- | ---- |
| NW201    | 85.0 |
| SE301    | 87.3 |

계산 과정을 단계로 따라가면 다음과 같다.

1. WHERE `점수 >= 70`이 55점(2406 NW201), 67점(2404 SE301), NULL(2402 NW201) 행을 제외한다.
2. 남은 행을 과목코드로 묶는다. DB101은 95, 72, 85, 78이고 NW201은 80, 90이고 SE301은 88, 91, 83이다.
3. 그룹별 평균을 계산한다.

```math
\text{DB101} = \frac{95+72+85+78}{4} = 82.5,\quad \text{NW201} = \frac{80+90}{2} = 85.0,\quad \text{SE301} = \frac{88+91+83}{3} \approx 87.3
```

4. HAVING `AVG(점수) >= 85`가 DB101(82.5)을 제외한다.

| 과목코드 | WHERE 후 행 수 | 평균 | HAVING 통과 |
| -------- | -------------- | ---- | ----------- |
| DB101    | 4              | 82.5 | 아니오      |
| NW201    | 2              | 85.0 | 예          |
| SE301    | 3              | 87.3 | 예          |

> [!IMPORTANT] 시험에서는 이렇게 묻는다
> GROUP BY 결과를 표로 쓰거나, `COUNT(*)`와 `COUNT(열)`의 차이를 이용해 값을 쓰게 한다. "WHERE 절에 집계 함수를 쓸 수 없으므로 그룹 조건에 쓰는 절"을 묻는 빈칸 문제도 나온다. 정답은 HAVING.

## 조인

### 조인의 종류

조인(Join)은 두 테이블의 행을 조건에 따라 이어 붙여 하나의 결과로 만드는 연산이다. 학생 테이블에는 학과코드만 있으므로, 학과명을 함께 보려면 학과 테이블과 조인해야 한다.
